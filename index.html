01 · problem

Remote tmux should not feel like swimming blind.

Laptop here. Workstation there. Sessions scatter; attach is friction; the green path across mosh gets lost in aliases and one-off scripts.

  • No shared picker for remote sessions
  • Host names remembered by myth
  • Errors after the connection is already live

02 · solution

A green ferry. Local command. Remote dock.

ferry

Daily short command. Mosh (or ssh) to the host that holds your sessions.

repo-session

On the remote: fzf picker, create, attach, claim — all tmux logic lives there.

Host-agnostic

Laptop ↔ workstation by default; nothing hard-coded to your names.

03 · pillars

What keeps the crossing honest

01

Picker-first

Default is the session menu — not a silent attach to the wrong pane.

02

Local errors

Validate before mosh when you can. Fail loud on this shore.

03

Doctor / update

Health checks and git-pull deploy via symlinks into the repo.

04

Green identity

Moss + mosh. Color is the signal. Name is clean on the forges.

04 · quickstart

Install both shores. Cast off.

npm on laptop and workstation. Click any line to copy.

setup
$ npm install -g mossferry ⎘
#1 Local + remote — bins: ferry · mossferry · repo-session
$ ferry doctor ⎘
#2 Health check this shore
$ ferry myhost ⎘
#3 Open the session picker on <host>
$ ferry doctor myhost ⎘
#4 Doctor the far shore over ssh
$ npx mossferry doctor ⎘
#1 Run without a global install
$ npx mossferry myhost ⎘
#2 Picker via npx
$ git clone https://github.com/muslewski/mossferry.git ⎘
#1 Clone on each machine
$ cd mossferry && ./install.sh ⎘
#2 Symlink into ~/.local/bin + seed config
$ ferry doctor ⎘
#3 Confirm PATH + config
✓ Remote host needs the same package (or repo-session) on PATH.
